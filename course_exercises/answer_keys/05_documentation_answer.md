# Answer Key 5: Ask AI to Write Documentation

Strong answers should:

1. Choose one clear model instead of trying to document the whole project
2. Explain what the model is for in plain English
3. Highlight important columns or business logic in a practical way
4. Include assumptions, limitations, or caveats where relevant
5. Make the documentation useful for another person reading the model for the first time

Common mistakes:

- Writing a generic summary that could apply to any model
- Failing to explain the purpose of the model
- Omitting key fields or important assumptions
- Producing documentation that is too vague to be useful
