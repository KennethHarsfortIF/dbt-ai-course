# Answer Key 5: Create Analysis

Strong answers should:

1. State the business question before writing SQL
2. Use `ref()` against existing marts or intermediate models instead of raw seeds
3. Define an exact output grain and metrics
4. Order or filter results so the output surfaces useful insights quickly
5. Include a short interpretation or assumptions section

Common mistakes:

- Querying raw tables directly when modeled tables already exist
- Mixing incompatible grains in one result set
- Returning a query with no stakeholder framing or explanation
